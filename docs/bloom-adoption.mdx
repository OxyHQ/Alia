# Bloom adoption

This is the Alia → Bloom map that [#608](https://github.com/OxyHQ/Alia/issues/608)'s
Definition of Done asks for. It describes the app as it is, not as it was
planned; the planning audit it replaces is summarised in [History](#7-history).

The app declares `@oxy.so/bloom` `^4.20.0` and resolves 4.20.0. Read the
contract from the installed package (`node_modules/@oxy.so/bloom/src/<family>/types.ts`),
never from the `~/Oxy/Bloom` checkout, and reach it only through public
subpaths — `packages/app/__tests__/bloom-boundaries.test.ts` fails on a deep
path or a sibling checkout. Where each file lives is
[the app architecture](./app-architecture.mdx).

The composition follows Bloom's AI Chat template
(`templates/ai-chat/AiChatTemplate.tsx` in the Bloom repository; the npm
tarball does not ship `templates/`): `AiChatShell` with a `Sidebar` and a right
panel, `AiChatContainer`, `AiChatThread`, the turns, the composer under them.
The router owns URLs and conversation identity; streaming, pagination,
authentication, voice, tools and inference stay in Alia
([chat runtime](./chat-runtime.mdx), [ADR 0001](./adr/0001-alia-oxy-kaana-responsibility-boundary.md)).

**composition** (Bloom exports assembled around Alia's data, with Alia's own
pieces where Bloom has none), **Bloom change** (a published Bloom release added
the contract Alia needed; the version is named) and **not applicable**.

## 3. Contract gaps

The ten gaps the planning audit found against 3.2.1. The Bloom commits that
closed them are named in Alia's bump commits (`f346746b` 3.3.0, `916e4eb9`
3.5.0, `d63ce122` 3.6.0, `c578c42d` 4.20.0).

| # | Gap | Status | How Alia uses it |
| --- | --- | --- | --- |
| 1 | No `onStop` on either composer | CLOSED 3.3.0 | `onStop` + `busy`; the stop ignores `disabled`. |
| 2 | The pill selected a model by its display name | CLOSED 3.3.0 | `ComposerPanel`'s picker takes `{id, name}` and reports the id. |
| 3 | <a id="gap-3"></a>`AiChatThread` had no timeline contract | PARTIAL 3.3.0; OPEN: no virtualization, no `scrollToIndex` | See below. |
| 4 | `AiChatContainer.project` was required | CLOSED 3.3.0 | Omitted for a new chat; otherwise the chat's project, folder or "Chats", as the sidebar files it. |
| 5 | Uploads had no real progress or failure | CLOSED 4.20.0 for `ComposerPanel` | Tiles carry the intake's measured `progress`, or `error` with a retry. `ComposerAttachments` still simulates and is not used. |
| 6 | The feedback row said "Copied!" regardless | CLOSED 4.20.0 | `copyText` returns what the clipboard answered; a refusal is an error toast. |
| 7 | <a id="gap-7"></a>Code and gallery panels default to demo actions and placeholders | OPEN (no Bloom change; avoided by explicit props) — partly | See below. |
| 8 | No layer behind the chat content | CLOSED 3.3.0 | `AiChatContainer.background` holds the field. |
| 9 | The picker's effort axis could not be absent | CLOSED 3.3.0 | `effortLevels={[]}` drops it; `effort={null}` is "no level chosen". |
| 10 | The shell could not collapse the sidebar | CLOSED 3.3.0, 3.6.0, 4.14.1 | Collapse, swipe-to-open and the closed drawer's `inert` are Bloom's; Alia's `NavRegion` wrapper went (`6b6414e7`). The app passes no `sidebarCollapsed`: the `Sidebar` sizes and animates itself. |

**Gap 3, cursor jump without `scrollToIndex`.** Long threads are windowed in
Alia, not virtualized: `src/features/chat/model/timeline.ts` mounts the newest
40 rows and reveals 30 more each time the reader nears the top, through the
same anchored `onStartReached` growth history paging uses. A cursor jump asks
the window to mount the target with 5 rows above it (`FOCUS_MARGIN`), and the
target row's `onLayout` calls `AiChatThreadHandle.scrollToOffset` with its
measured `y` (`handleFocusLayout` in `chat-interface.tsx`). `VirtualList`
cannot host the thread: its `onEndReached` fires at the end while a chat pages
upward, and react-native-web ignores `maintainVisibleContentPosition`. Measured
in [the runtime baseline](./runtime-baseline.mdx#10-the-timeline-at-1000-and-5000-messages).

**Gap 7, what the explicit props do and do not cover.** The composer passes
`addMenu` and `permissions` always (an empty list hides each), so Bloom's
demo menus never show, and the status tab gets only the project. The code
panel passes its own `actions` (the terminal only where there is an agent, and
close) and a `browser` node for the terminal or a non-code canvas. Still
showing Bloom defaults, with no handler behind them:

- **The gallery panel** passes neither `actions` nor `stylePresets`, so it
  draws `DEFAULT_GALLERY_PANEL_ACTIONS` (new generation, expand, toggle — no
  `onPress`, English labels) and a "Style presets" tab with a placeholder;
  without `onDownload` / `onMore`, each image's scrim buttons do nothing.
- **The code panel's summary** is always drawn (`changeCount` is always
  passed), and with it an "Undo changes" button with no `onUndo`, and `-0`.
- **The code panel's Browser tab** shows the "Browser preview" placeholder
  while the canvas holds code and there is no agent terminal.

Each is a #608 §1.6 violation to fix in Alia (pass the props, or give the tab
real content), not a Bloom gap.

## 5. Still different from the template, or from the app before #608

Verified in the code on the integration branch.

- **Sidebar.** No keyboard-shortcuts row; the dialog opens with ⌘/ (web). A
  folder cannot be favourited: the folder type has an `isFavorite` field
  (`src/features/projects/runtime/folders-store.ts`) that nothing sets or
  reads. The foot is Oxy's `ProfileButton` rather than the template's account
  row and plan card; upgrading is in its menu.
- **Chat header.** No share button: the container's `actions` replace Bloom's
  share/more, and the menu offers search, the panel, the agent terminal,
  usage, export Markdown, clear and delete. Ghost mode moved from the header
  to the composer's add menu.
- **Warnings.** Low credits, the spending warning and the local-models invite
  are Bloom toasts; the invite has no artwork (a toast has no image slot). The
  "limit reached" banner is `UsageLimitDialog`.
- **Composer.** Dictation is the panel's mic: it records and transcribes into
  the draft, with no separate cancel/send bar.
- **Thread.** "Generate audio" is not offered: `POST /v1/audio/generate`
  answers `unavailable` to every request (`packages/api/src/routes/v1/audio.ts`).
- **Look.** The colour preset is `purple` (`app/_layout.tsx`); Bloom's
  Storybook shows the template in `oxy`. Below `lg` (1024) the sidebar is a
  drawer; before #608 it was in flow from 768.

## 7. History

#608 was written against Bloom 3.2.1. The first audit (`726bd699` onward)
found the app importing 18 Bloom subpaths and **no AI family**, and the ten
