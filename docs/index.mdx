# Alia

Alia is Oxy's assistant. One runtime serves the Expo app (web, iOS, Android), the
Codea VS Code extension and CLI, the Cowork desktop client, other Oxy apps and
third parties through the SDK. Alia acts for the person in their Oxy apps, runs
tasks in the background, writes first when something needs them, and lets people
create **agents** — personas with their own Oxy account, memory and computer.

## What it is

A single chat runtime (`/alia/chat` and `/v1/chat/completions`) serves every surface. Each turn is taken by an actor — Alia, or one of the person's agents ([actors](./actors.mdx)) — runs the autonomy loop `classify → recall → retrieve → act → learn` ([memory and the context graph](./memory-system.md)), and is governed by the risk policy `R0`–`R3` ([governance](./agents.md#governance)).

Alia is one of three things, and the three are not nested
([ADR 0010](./adr/0010-alia-keeps-a-product-api-credentials-come-from-oxy-console.md)):

- **Kaana** — the inference API. Models only; provider credentials live there.
- **Oxy** — the platform and Oxy Console. Accounts, applications, **all** API keys for
  Alia, Kaana and Mention, billing.
- **Alia** — the assistant, with its own **permanent product API** (`api.alia.onl/v1/*`
  and `/alia/chat`, plus the product routes beside them). Three groups call it, all
  authorized by Oxy: Alia's own surfaces — the app, Codea (extension and CLI) and Cowork,
  on `/alia/chat` with the user's Oxy session; other applications in the Oxy ecosystem;
  and third parties through `@alia.onl/sdk`. It accepts an OpenAI-compatible request
  shape and streams `alia.*` product events; it does not sunset.

For raw model access use Kaana through Oxy (`api.oxy.so/v1`); for the assistant use
Alia's API. Either way the key is issued in Oxy Console — Alia issues none.

Hosted inference follows `Alia -> Oxy -> Kaana`. Alia has no models of its own:
a person picks a power level (`auto` … `ultra`) and Oxy picks the model of that
level ([ADR 0014](./adr/0014-people-choose-power-levels-not-models.md)); API
callers may still name a real `<publisher>/<model>` from Oxy's catalogue
([ADR 0012](./adr/0012-alia-uses-real-models.md)). Oxy authenticates the caller
and signs the exact ordered deployments; Kaana owns provider credentials,
deployment execution, health and failover within that order. [Model
abstraction](./model-abstraction.mdx) describes the boundary, and [ADR
0003](./adr/0003-model-revision-deployment-provider-routing-profile.md) records
the vocabulary behind it.

## Architecture

```
                            +-------------------+
                            |   Expo App (Web,  |
     User  ────────────────>|   iOS, Android)   |
                            +---------+---------+
                                      |
                            POST /alia/chat (SSE)
                                      |
                            +---------v---------+
                            |  Express API      |
                            |  (packages/api)   |
                            +--+----------+-----+
                               |          |
              +----------------+          +-----------------+
              |                                             |
     +--------v---------+                       +-----------v-----------+
     |   PostgreSQL     |                       |  Oxy inference edge   |
     |   (drizzle)      |                       +-----------+-----------+
     +--------+---------+                                   |
                                                  +---------v---------+
                                                  | Kaana data plane  |
                                                  +-------------------+
     +--------v---------+
     |  Redis (Valkey)  |     Socket.IO (real-time events,
     |  rate limits,    |     approval requests, streaming)
     |  caching         |
     +------------------+
```

Beside these, the API reaches the person's Oxy apps through Oxy's capability tickets
([integrations](./integrations.mdx#oxy-apps)), and the agents' computer host
(`packages/alia-computer-host`, its own EC2 Spot instance) over the internal network
([actors](./actors.mdx#the-agents-computer)).

PostgreSQL is Alia's only product store: conversations, messages, agents, organizations, skills and the rest. Under [ADR 0001](./adr/0001-alia-oxy-kaana-responsibility-boundary.md), every hosted inference call crosses the published Oxy inference client and Oxy calls Kaana; only a user's explicitly connected local runtime stays outside that hop.

| App | Stack | Purpose |
| --- | --- | --- |
| `packages/app` | Expo + React Native | Main app (web + iOS + Android) |
| `packages/api` | Express + TypeScript | Core API runtime |
| `packages/alia-codea` | VS Code extension | Coding assistant surface |
| `packages/alia-codea-cli` | Bun CLI | Terminal coding assistant |
| `packages/alia-cowork` | Electron | Desktop assistant surface |
| `packages/alia-canvas` | Vite + React | Canvas / diagram editor |
| `packages/integrations` | Express + TypeScript | Telegram / WhatsApp / Discord / browser bridges, and the MCP client |
| `packages/alia-chat` | React | Published as `@alia.onl/sdk` — the CLIENT SDK (components, hooks, voice) |
| `packages/alia-server` | TypeScript | Published as `@alia.onl/server` — the SERVER client a consumer backend calls Alia with |
| `packages/alia-computer-host` | Node + Docker (gVisor) | The agents' computer: sandboxed machines and browser, on its own Spot host ([actors](./actors.mdx#the-agents-computer)) |

## Install

The monorepo uses Bun workspaces — no Turborepo or Nx; root scripts fan out with `bun run --filter`. Bun is the only supported package manager.

```sh
bun install
```

Copy `packages/api/.env.example` to `packages/api/.env` and fill it in. `DATABASE_URL` is the only database variable and the API refuses to boot without it. Hosted provider credentials are not Alia environment variables or database rows; Kaana stores and uses them in its own PostgreSQL database. Alia authenticates to Oxy with its Oxy application service credential, and Oxy is the only hop that calls Kaana.

## Quick start

Boot the full stack:

```sh
bun run dev
```

Or run individual workspaces:

```sh
bun run dev:api          # Express API only
bun run dev:app          # Expo app (web + tunnel)
bun run dev:canvas       # Canvas app
bun run dev:codea        # VS Code extension
bun run dev:cowork       # Electron desktop app
```

Hit the unified chat endpoint:

```ts
const res = await fetch('https://api.alia.onl/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer <oxy-session-token>',
  },
  body: JSON.stringify({
    model: 'auto', // a power level (ADR 0014), or a real <publisher>/<model>
    messages: [{ role: 'user', content: 'Prepare my meeting with Sarah' }],
    stream: true,
  }),
});
// SSE stream — see "Chat runtime" for the event contract.
```

The bearer is an Oxy credential: a user session or service token today (`packages/api/src/middleware/auth.ts`), an application key from Oxy Console once that path is built. The `alia_sk_*` keys are retired and refused — see [developer access](./developers-portal.md).
