# Models in Alia

Alia has no models of its own. A person chooses a **power level** — Auto (the
default), Instant, Medium, High, XHigh, Pro, Ultra — and Oxy picks an available
model of that level for each request, through Kaana. Oxy authenticates,
authorizes, chooses the model and resolves the deployment; Kaana owns provider
credentials, deployment execution, health and failover. API callers may still
name a real `<publisher>/<model>`. The decisions are
[ADR 0014](./adr/0014-people-choose-power-levels-not-models.md) and
[ADR 0012](./adr/0012-alia-uses-real-models.md).

**Nothing about models is hardcoded.** There are no model ids in code or in
environment variables, and no curated lists. The seven power levels are Oxy's
fixed routing-profile vocabulary, not models; which models belong to each is
reviewed data in Oxy. The catalogue comes from Oxy, and every model Alia chooses
itself — featured models, the utility model, the speech model — is computed from
that catalogue and from Alia's own usage.

There is no hosted direct-provider mode in Alia. Provider environment keys and
`GATEWAY_API_URL` are refused at boot rather than treated as alternate
configuration.

## Model identity

A request's `model` is one of:

- **a power level** — `auto`, `instant`, `medium`, `high`, `xhigh`, `pro`,
  `ultra`. It is sent to Oxy as `routingProfile`; the response names the model
  that ran. This is what Alia's app sends.
- **`<publisher>/<model>`** — a model from the catalogue, e.g. the id a picker
  entry carries. It is sent to Oxy as `model` unchanged.
- **`local/<runtime>/<model>`** — a model served by the person's own device
  ([ADR 0007](./adr/0007-a-users-own-machine-as-an-inference-runtime.md)). It
  never reaches Oxy and reserves no credits.
- **absent** — `auto`.

Anything else, including the retired `mode:*` and `route:*` spellings and any id
the catalogue does not carry, is refused before credits are reserved:

```json
{
  "error": {
    "message": "\"acme/unknown\" is not an available model or power level. Name a power level (auto, instant, medium, high, xhigh, pro, ultra) or a model listed at GET /catalogue.",
    "type": "invalid_request_error",
    "param": "model",
    "code": "model_not_found"
  }
}
```

There are no Alia-owned product modes or aliases. Deep research and agent mode
are request flags and run at the chosen level.

## Power levels

| Level | What Oxy picks | Effort | In the app |
| --- | --- | --- | --- |
| `auto` | the cheapest level that suffices, per request (never `pro`/`ultra`) | the level's | Picks the right level for each message |
| `instant` | very cheap, fast small models | none | Fastest and cheapest |
| `medium` | mid-size models | `low` | Everyday tasks |
| `high` | strong models | `medium` | Tougher questions |
| `xhigh` | the `high` models | `high` | Thinks even harder |
| `pro` | frontier models | `high` | Slower, costs more |
| `ultra` | the heaviest frontier models | `high` | Most capable, slowest |

Membership, ordering and failover inside a level are Oxy's
(`oxy/docs/inference/power-levels.md`). Alia never retries or swaps a model
itself. It reads the model that ran from the response
(`providerMetadata.kaana.resolvedModelReference`), prices the turn by it, and
records it as `chat_analytics.model` with the level as the requested model.

## The catalogue

`GET /catalogue` is built from `OxyInferenceClient.listModels()` (`@oxy.so/core`),
cached for five minutes, and filtered to what the chat can use: **text in, text
out, and tool calls supported**. A model a provider retires disappears on the
next refresh without a deploy.

```json
{
  "object": "list",
  "defaultModelId": "acme/chat-large",
  "featuredIds": ["acme/chat-large", "example/reasoner-2"],
  "data": [
    {
      "id": "acme/chat-large",
      "object": "model",
      "name": "Chat Large",
      "publisher": { "id": "acme", "name": "Acme" },
      "description": null,
      "contextWindow": 131072,
      "maxOutput": 16384,
      "inputModalities": ["text", "image"],
      "outputModalities": ["text"],
      "tools": true,
      "reasoningEfforts": ["low", "medium", "high"],
      "pricing": { "inputPerMTok": "0.15", "outputPerMTok": "0.60" },
      "releasedAt": "2026-08-01",
      "featured": true
    }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `id` | `<publisher>/<model>`; what a request sends as `model`. |
| `name`, `publisher` | Display name and publisher (`id` is the publisher slug). |
| `description` | Oxy's description, or `null`. |
| `contextWindow`, `maxOutput` | Token limits, or `null` when unknown. |
| `inputModalities`, `outputModalities` | `text`, `image`, `audio`, `video`, `embedding`. |
| `tools` | Always `true` in this list; kept so clients need no inference. |
| `reasoningEfforts` | Effort levels the model accepts; `[]` hides the effort control. |
| `pricing` | USD per million input/output tokens as decimal strings, or `null`. |
| `releasedAt` | Release date from the catalogue, or `null`. |
| `featured` | Whether the model is in `featuredIds`. |

`featuredIds` is ordered. `defaultModelId` is the model a client that still
renders a model picker should preselect for this person (the one they last
used, else a computed one); a request that names nothing does not run on it.
The response also carries `powerLevels` (the seven slugs) and
`defaultPowerLevel` (`auto`).

`GET /v1/models` returns the same list in the OpenAI shape
(`{ "object": "list", "data": [{ "id", "object": "model", "created", "owned_by" }] }`,
`owned_by` being the publisher id). `GET /catalogue/modes` no longer exists.

## Automatic choices

The selection rules are pure functions over the catalogue and usage data
(`packages/api/src/lib/models/`):

- **Stable release** — what Alia chooses for somebody is priced above zero (a
  free tier is throttled and withdrawn without notice) and carries no
  pre-release marker (`preview`, `exp`, `beta`, `alpha`) in its id or name.
  Other models stay selectable in the picker.
- **Featured** — for each publisher, its newest stable chat-usable model (by
  `releasedAt`), publishers ranked by Alia's real usage over the last 30 days
  (`chat_analytics`), then by how many chat models they have in the catalogue;
  top dozen. Recomputed daily.
- **Preselected model for a person** (`defaultModelId`, for model-picker
  clients) — the model they last used; otherwise the most-used featured model in
  Alia; on a cold start, the median-priced featured model. A request that names
  nothing runs `auto`, not this model.
- **Utility model** — titles, summaries, compaction, suggestions, soul, style
  refinement, planner, verifier and other internal calls use the cheapest
  stable chat-usable model with a context window of at least 32k tokens.
- **Speech model** — the cheapest catalogue model with audio output.

Stored choices hold a power level, a real model id or `NULL`:
`agents.model_id`, `agent_threads.model_id`, a bot's default/preferred model and
a canvas node's model. `NULL` means `auto`, and a stored id the catalogue no
longer carries falls back the same way.

## Reasoning effort

`reasoningEffort` is `low`, `medium` or `high`. With a power level it is
optional (the level sets its own) and any of the three is accepted: Oxy keeps
only the level's models that take it. With a model it is accepted only when the
model lists that level in `reasoningEfforts`; otherwise the request is refused
with `param: "reasoningEffort"`. It is forwarded to Oxy as
`reasoning: { effort }`, and Oxy and Kaana translate it for each provider. Alia
keeps no per-provider reasoning table, and no model name encodes a reasoning
level.

## Hosted request path

For hosted text inference:

1. The request boundary resolves `model` — a power level, or a model against
   the catalogue; absent is `auto` — and validates `reasoningEffort`.
2. `packages/api/src/lib/chat-core.ts` produces a credential-free resolution
   whose Oxy target is `{ kind: 'routingProfile', routingProfile: '<level>' }`
   or `{ kind: 'model', model: '<publisher>/<model>' }`.
3. `getAIModel()` returns the Kaana AI SDK adapter.
4. `@oxy.so/core`'s `OxyInferenceClient` authenticates to Oxy with Alia's
   short-lived service credential.
5. Oxy resolves identity and authorised routes, then signs and forwards the
   request to Kaana. Kaana owns every provider-side execution decision.

Alia performs one hosted attempt. It does not rotate provider keys, construct
provider clients or substitute a different model after an error.

The one explicit exception is a user's connected local runtime. That path uses
the user's own runtime binding and intercepted fetch bridge; it never becomes a
hosted fallback and never uses a provider environment key.

## Prompts

The system prompt is chosen by the **surface** the turn comes from — chat,
Codea, Cowork or voice — never by the model. There is no extended-reasoning
prompt layer; effort is a model parameter.

## Credits and plans

A turn is charged by its real cost: the unit prices of the model that ran (for
a power level, the one Oxy names on the response) as published by Oxy, applied
to the units metered for that turn, converted at one fixed rate
(`USD_PER_CREDIT` in `packages/api/src/lib/credits-manager.ts`). A model without
published prices is charged at the base token rate and logged. There are no
per-model multipliers.

Every plan can use every model. Plans differ only in how many credits they
grant; `plans.model_ids` no longer exists.

## Capabilities

Text chat uses the Kaana seam. Speech uses the typed
`OxyInferenceClient.speech` operation with delegated user identity and the
computed speech model. MP3 output is stored privately and returned as a
short-lived playback link. See the
[speech recovery record](./runbooks/speech-recovery-2026-09-13.md) for rollout
history.

Hosted image generation, transcription, voice sessions and embeddings do not
yet have a Kaana capability seam. Those routes fail closed with HTTP 503 and
`KAANA_CAPABILITY_UNAVAILABLE` before provider selection, billing or egress.

## Names on the product surface

The app shows power levels, never hosted model names. Model and publisher
names may appear in API responses and analytics. The **operator serving a deployment** (Groq, Cerebras, OpenRouter and
the like) and **deployment identifiers** stay off the product surface — product
API responses, errors, the UI and customer-facing analytics. `sanitizeMessage()`
remains the product-surface guard; logs, audit and licence attribution may carry
what they need.

## Credentials and retained migration data

Provider credentials belong to Kaana's database. Alia does not read provider
API keys from its environment and cannot enable hosted inference with one.
Migration `packages/api/drizzle/0061_remove_alia_provider_credentials.sql`
dropped Alia's legacy `provider_keys` table without reading its contents; the
routing-profile tables were dropped by migration 0070, and the routing-profile
catalogue that replaced them in code is deleted under ADR 0012. Applying
destructive migrations in production still requires the readback in the
[Kaana cutover runbook](./runbooks/kaana-cutover.md).
