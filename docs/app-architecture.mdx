# App architecture

`packages/app` keeps its routes in `app/` (expo-router) and everything else in
`src/`. The `@/` alias means `src/` — in `tsconfig.json` (which Metro reads) and
`vitest.config.ts` alike — and `global.css` scans `src/**` for NativeWind
classes. Metro is `@oxy.so/app-preset`'s `createOxyMetroConfig`
(`metro.config.js`).

Development and production bundles both go through Babel (`babel.config.js` is
the one line `require('@oxy.so/app-preset/babel')`). Noxcturnal, Expo's oxc
transformer (`experiments.noxcturnalTransformWorker`), stays off: its 0.1.x
releases miscompile `@tanstack/query-core`'s `QueriesObserver` on web — the
temporary that holds the lowered constructor's return value reuses the name of
the `#result` private key — so every `useQueries` throws "attempted to use
private field on non-instance" in development only. Turn it back on only with a
release that compiles that class correctly.

```
packages/app/
  app/                      routes; thin — each composes a feature's screen
  fixtures/                 validation fixtures, web-only, behind EXPO_PUBLIC_ALIA_FIXTURES
  __tests__/                gates about the whole package (bloom, feature boundaries, …)
  src/
    shell/                  the frame: sidebar, command palette, workspace panel, error boundary
    features/<feature>/
      ui/                   components
      runtime/              hooks, stores, sockets — anything with a lifecycle
      model/                pure code: parsing, formatting, selection, types
    shared/
      api/                  API client, routes, query factory and keys, error text
      contracts/            types (and pure labels) that more than one feature reads
      routing/              addresses outside the app (a gemie's thread on gemies.ai)
      format/               file size, relative time, title tags
      i18n/                 catalogs, `useTranslation`, locale store
      platform/             config, keyboard, colour scheme, pickers, sounds, device
      state/                account scoping, the collection store factory
      ui/                   logo, image, generated icons — draws what it is handed
      testing/              stubs and helpers only tests import
```

The features are `chat`, `voice`, `memory`, `library`, `projects`, `shows`,
`skills`, `connections`, `local-models`, `billing`, `onboarding`,
`notifications` and `settings`. A test sits in `__tests__/` beside the layer it
mainly tests.

The app is Alia's alone (Gemies ADR 0034): it talks only to the Alia gemie.
The person's other gemies — their list, the catalogue, a gemie's page, editor
and computer, groups, spaces and external agents — live in the Gemies app
(`https://gemies.ai`). The account menu links there, a push about a gemie opens
its thread there, and the web Worker sends the old `/@handle` and `/agents`
addresses there (`packages/app/worker/index.js`). The sidebar and the command
palette list only Alia's chats (`isAliaChat` in `src/shell/sidebar-history.ts`);
what Alia learns by consulting another gemie stays inside her chat.

## Who may import whom

`shared/` imports only `shared/`. The shell imports features; no feature imports
the shell. Between features, only these edges exist:

| Feature | May import |
| --- | --- |
| shell | chat, library, memory, onboarding, projects, settings, shows |
| settings | billing, chat, connections, library, local-models, memory, notifications, skills |
| chat | billing, connections, local-models, memory, notifications, projects, skills, voice |
| shows | notifications |

Every other feature imports only `shared/`. The graph has no cycle. When two
features need the same type, it goes to `shared/contracts` rather than one
reaching into the other: voice and the chat both send a turn shaped by
`shared/contracts/chat-turn.ts`. What a conversation draws — the thread, its
cards, the thought panel, the work log, the composer's levels, the voice call —
is not an app feature at all: it is the SDK's (see the chat's section below).

## The chat is the SDK's; this is what the app keeps

A conversation is drawn by `@gemies/sdk` (`GemieChatContent`, the same screen the bottom sheet
mounts: [the chat runtime](https://github.com/OxyHQ/Gemies/blob/main/docs/chat-runtime.mdx#the-conversation-screen-is-the-sdks-too) in OxyHQ/Gemies). What stays
in `src/features/chat` is only what is the app's:

| Where | What | Why it is the app's |
| --- | --- | --- |
| `ui/conversation-screen.tsx` | the one screen behind `/` and `/c/:id`: which power level and devices, the add menu, the project crumb, the usage dialog, toasts of the account | it composes the app's data (stores, plans, router) into the SDK screen's slots |
| `ui/conversation-actions.tsx`, `ui/chat-header-actions.tsx` | search, share, export, clear, delete, the panel toggle | the right panel, the router and where an export goes |
| `ui/chat-labels-provider.tsx` | the catalogue (`t`, `locale`) and the composer's and the call's words | the app translates; the SDK ships English |
| `ui/chat-workspace.tsx` | the keyboard frame and the container of the screens that are not a conversation (intro, loading) | layout |
| `ui/welcome-intro.tsx` | the signed-out intro | a route concern |
| `ui/workspace/*` | credits and limits | the right panel's contents |
| `ui/composer/add-menu.tsx`, `use-alia-composer.ts` | the add menu's rows and the composers of the screens that create a skill or a task | capabilities, skills, connectors, entitlements and the library are the app's |
| `ui/composer/power-level-options.ts` | which devices are connected | the app knows its devices; the levels are the SDK's |
| `runtime/ui-store.ts` | the right panel, the sidebar, the canvas, the panel width | layout; what the thread selected (the thought panel's turn) is the SDK's `useThoughtStore` |
| `runtime/use-alia-host.ts`, `use-alia-speech.ts`, `use-app-voice-options.ts` | what the app tells the SDK about itself | navigation, credits, memory, plan gates |
| `runtime/*` stores (`global-store`, `model-store`, …), `model/*` | the app's own state and pure helpers (capabilities, turn selection, context usage) | the app's |

## The gate

`packages/app/__tests__/feature-boundaries.test.ts` runs with the app suite in
CI. It reads every specifier — imports, re-exports, `import()`, type imports,
`require`, `vi.mock` — with the TypeScript parser and fails when:

1. a file under `src/` is outside `shell/`, `features/<x>/{ui,runtime,model}/`
   or `shared/<y>/` (there is no `src/app`: expo-router would take it for the
   routes directory);
2. features form a cycle, type-only imports included;
3. a feature edge is not in the table above (`ALLOWED` in the test), or an
   allowed edge is no longer used;
4. `shared/` imports a feature, the shell or a route;
5. `shared/ui` imports `shared/api`, `@tanstack/react-query`, `socket.io-client`
   or `zustand`;
6. a feature imports the shell;
7. `src/` imports a route or a fixture, or production code imports
   `shared/testing`;
8. anything names the old `components/`, `lib/`, `types/` or `test/` layout.

Tests are exempt from rules 2–6. Each rule has a positive control that runs the
same check against a tree built to break it. A new edge is a decision: add it
to `ALLOWED` and to the table above in the same change, or move what both sides
need into `shared/contracts`. How Bloom is reached is
`__tests__/bloom-boundaries.test.ts`.

## Moving a branch across

The tree was produced by `packages/app/scripts/move-to-features.ts`, which maps
each old file to its place, `git mv`s it and rewrites every specifier and path
that named it. It is idempotent; its header says how to bring a branch cut
before the move across.
