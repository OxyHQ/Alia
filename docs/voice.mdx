# Voice

Since `@alia.onl/sdk` 15.0.0 ([ADR 0017](./adr/0017-voice-is-a-realtime-session-through-kaana.md)),
no surface uses the browser's or the operating system's speech recognition.

| Feature | Hook | What it does | Route |
|---|---|---|---|
| Voice call | `useVoiceRoom` (screen: `VoiceSession` / `useVoiceLauncher`) | A spoken conversation, full duplex, turn detection and barge-in on the server | `GET /v1/voice/session` (WebSocket) |
| Dictation | `useDictation` (in `AliaComposer`) | The composer's microphone: one recorded clip becomes text in the draft | `POST /v1/audio/transcriptions` |
| Read aloud | `useTTS` | A message, spoken on request (unchanged) | `POST /v1/audio/speech` |

## Status (ADR 0017 phase 1)

Alia reaches Kaana's one canonical API (Kaana ADR 0003) through `@kaana.ai/sdk` 3.0.0
and `@kaana.ai/contracts` 6.0.0. `packages/api/src/lib/kaana/port.ts` is a narrow port
whose members are the `Kaana` client's own (function properties, so a mismatch fails
the typecheck); every shape is the SDK's and the contract's, none restated. It is
tested against `@kaana.ai/sdk/testing`: the same client against Kaana's own schemas,
checks and voice catalogue in memory, so a request the tests accept is one Kaana
accepts.
`lib/kaana/transport.ts` is the one place the client is constructed: the real SDK,
whose credential is Alia's Oxy service token with `aud: kaana.ai`
(`oxyServiceTokenFor`, @oxy.so/core 4.9.1), minted from the same identity as every
other Alia call to Oxy. A process with no Oxy service identity has no client, and
then a call ends `realtime-unavailable` and dictation answers
`TRANSCRIPTION_UNAVAILABLE` — typed, never a stand-in. So does every call while
Kaana's public API is off (`KAANA_PUBLIC_API_ENABLED`, oxy-infra runbook 48).

What production still needs, outside Alia, is in [What is left](#what-is-left).

## A call

```text
app / SDK ──WSS /v1/voice/session──▶ Alia API ──@kaana.ai/sdk realtime.connect──▶ kaana.ai/v1/realtime ──▶ provider
  PCM16 24 kHz binary frames             │  instructions, tools, memory,
  + Alia's JSON events                   │  tool execution, persistence,
                                         │  credits, typed errors
```

Alia is the only client of the Kaana session. The device sends microphone audio and
receives the answer's audio, transcripts and a few events for the call UI; it never
sees an instruction, a tool schema, tool arguments or a tool result. Alia connects
under its service token (`aud: kaana.ai`) with the person as delegated attribution
(`onBehalfOfUserId`): lane `service_token`, relationship `alia-kaana`.

### The socket

`lib/voice/voice-socket.ts` mounts `GET /v1/voice/session` with `ws` in `noServer`
mode on the shared HTTP server, exactly as `lib/mcp-relay.ts` does, so socket.io's
handshake is never stomped. The protocol is `lib/voice/protocol.ts` (the SDK keeps its
own copy in `src/lib/voice-protocol.ts`; `VOICE_PROTOCOL_VERSION` makes a mismatch a
refusal):

```text
client: auth { token }                       an Oxy session of Alia's own apps
alia:   auth.ok
client: session.start { protocol: 2, conversationId, agentId?, voice, locale }
        | session.resume { protocol: 2, voiceSessionId, afterSeq }
alia:   session.accepted { voiceSessionId, callId }     still connecting
alia:   session.ready { model, maxDurationMs, … }       Kaana created the session
client: <binary PCM16 24 kHz mono, ~40 ms frames>
alia:   input.ready                                     the first frame was appended
alia:   user.speech_started / user.speech_stopped, transcript.delta|done { role, messageId, itemId },
        <binary [u8 n][item id][PCM16]>, assistant.audio_done, assistant.done,
        tool.started / tool.finished { messageId, name }, messages.saved,
        session.warning { ending-soon }, session.reconnecting, session.resumed,
        error { code, retryable, reference }, session.closed { reason }
client: playback.interrupted { itemId, playedMs }, session.end, auth { token } (refresh)
```

Every event after `session.accepted` carries `seq`, which is what a resume replays
from. **Only a person's session is accepted**; an `oxy_sk_` machine credential is
refused with `credential-not-supported` (third parties are a later decision).

### Opening, in order

`lib/voice/call.ts` (`VoiceCall.open`):

1. The turn's inputs from the identity — memory, Oxy profile, entitlements and the
   agent — through `prefetchTurnInputs` (`lib/chat/turn-inputs.ts`), the same reads
   a typed turn makes (extracted from `buildChatRequestContext`).
2. **`voice-mode` is enforced by the server** (`plan-required`), not only by the app.
3. The agent: a person's own or a public one (`loadTurnAgent`); a product's agent is
   refused (`agent-unavailable`) — it is reached through its application's lane.
4. The realtime model, computed (below). No candidate: `realtime-unavailable`.
5. The first credit block (below). Refused: `credits-exhausted`.
6. **One call per person** (below): this call takes over any other.
7. The conversation's stored messages, the tools and the instructions.
8. Kaana. The client stays `connecting` until `session.created` (`session.ready`).

### The model is computed; power levels do not choose it

`rankRealtimeCandidates` (`lib/models/voice-models.ts`) reads Kaana's catalogue at
open: a `conversation` session over `websocket`, tools, audio in and out, and the
model's own input transcription (`capabilities.realtime.inputAudioTranscription`); a
voice of the product gender (`male` | `female`); active. The cheapest
`pricePerMinute` first. No model is chosen or excluded for its language: the person's
BCP 47 locale is sent as it is (`inputAudioTranscription.language`), and Kaana gives
every model the language. Nor does Alia set the silence that ends a turn: that is
Kaana's default (`REALTIME_DEFAULT_SILENCE_DURATION_MS`), the same on every provider.
The upstream voice id is
sent to Kaana and never shown or returned. The open is tried on at most two
candidates, and only when the model itself refused (`model_not_found`,
`unsupported_modality`, `no_route_available`, `invalid_request` on `voice`/`config`);
authentication, credit and rate refusals fail at once. The served revision
(`session.created`) is what the call is priced with and what `chat_analytics`
records (`platform: 'voice'`, never anybody's default chat model). Model and publisher
names may be shown; the operator never.

The person's power level still governs the inference a tool runs during the call.

### What the session is opened with

- **Instructions:** `SystemPromptBuilder.buildMeasured({ responseMode: 'voice' })` —
  `prompts/voice.md` and no question card — plus the recent conversation as one text
  section (never one billable item per message) and the session language
  (`lib/voice/turn.ts`). Within the contract's 32 768 characters: the history shrinks
  first, then the recalled memories go; if the base prompt alone does not fit, the
  call refuses to open (`realtime-rejected`) rather than cut it.
- **Memory per actor:** an Alia call has the person's memory and the
  `saveUserMemory` family; an agent's call has `agent_memory_documents` and its
  `memory` tool. Memories are recalled at open.
- **Tools:** `ToolPipeline.forUser` with the person on the socket as
  `requesterAccountId`, so an agent's `oxy_*` tools reach its owner's apps only when
  the owner is the one talking (ADR 0015). Serialized with
  `asSchema(...).jsonSchema`, at most 128, starting from the routed active set; a
  `loadTools` call widens the session with `session.update { tools }`.
- **Turn detection:** `server_vad` with `createResponse` and `interruptResponse` (the
  one mode every provider accepts); `inputAudioTranscription { language }`; PCM16
  24 kHz both ways.
- **Limits** (Alia product rules, not capacity): 30 min, 2 min idle, 500 responses,
  no text items, audio bytes for 30 min each way.

### Tools run in Alia

On a complete `tool_call`, `runTool` (`lib/voice/tool-bridge.ts`) executes the tool
by name in Alia, bounded by 60 s; the result goes back as
`conversation.item.create { function_call_output }`, then `response.create`. A failure,
unknown tool, bad arguments or timeout is a typed tool error the model reads — never
an invented result. The client gets `tool.started` / `tool.finished` with the tool's
name, for the call UI. Nothing in a call asks for approval (ADR 0020 §3): a tool
effect runs under the actor's Oxy authority, as in chat.

### Barge-in

The provider detects the turns. On `input_audio.speech_started` Alia forwards
`user.speech_started`; the client flushes its playback and reports how many
milliseconds of the current item it actually played (`playback.interrupted`); Alia
sends `conversation.item.truncate { audioEndMs }`, so the model remembers what was
heard. There is no end-of-utterance timer and no echo heuristic anywhere.

### Transcripts become messages

Each exchange is appended as it completes (`appendConversationMessages`,
`lib/conversation-saver.ts`, the next `seq`, retried on a concurrent append): the
person's words from the session's own input transcription, and the answer from its
output transcript with the tool round trips. An interrupted answer is stored whole,
with `messages.interrupted_after_ms` = what was heard. A response with no output
stores nothing. The open client is told twice: `messages.saved` on the call's socket
and `conversation:message` on socket.io, which appends to the open thread. The first
words of a new conversation title it.

**One id per message, from the first word.** Every `transcript.delta|done` and
`tool.started|finished` names `messageId`, the id the message is stored and announced
under; the client draws one message per `messageId` (an assistant turn's items and its
tools are one message, as stored). So the stored copy that `conversation:message`
brings is the message already on screen, never a second one, and once a message is
saved the thread shows the stored copy (`lib/call-thread.ts`): the one a reload or a
resume shows, with its tools' arguments and results, which the call's socket never
carries. That wire is protocol 2; a protocol-1 client (one bubble per audio item) is
refused with `invalid-request` rather than served wrongly.

**When the person's words are final.** A provider may send several `transcript.done`
for one input item: xAI sends a growing transcript at every pause, repeats it, reuses
the item across pauses and sends its final one only after the item is committed
(measured 2026-10-16); OpenAI commits first and sends one. Each `done` replaces the
last, the first `done` after `input_audio.committed` is final, and an item is stored
once: a later event of it is never a second message. An item with no final transcript
is stored as it stands `userTranscriptWaitMs` (8 s) after its last event.

### One call per person

`voice_calls` (`db/schema/voice.ts`, migration `0094_voice_calls`, pre phase) with a
partial unique index on `oxy_user_id WHERE status = 'active'`.
`lib/voice/call-registry.ts`:

- A start takes over in one transaction under
  `pg_advisory_xact_lock(hashtextextended('alia:voice-call:' || user, 0))`: the
  active row ends `moved_elsewhere` (live lease or not) and the new one is inserted.
- Same task: the old call is hung up directly. Another task: `takeover` on the Redis
  channel `alia:voice-call`. Without Redis, the 10 s lease renewal that matches no
  active row hangs the old call up — the worst overlap is one renewal, and it is
  billed.
- The old call stores its messages, closes its Kaana session and announces `ended`;
  the new call waits for it at most 2 s before reading the conversation.
- The old device ends with `session.closed { reason: 'call-moved-elsewhere' }`, a
  reason, not an error. Dictation is not a call. A resume is the same call.

### Reconnection and ending

- **Client ↔ Alia:** a dropped socket keeps the call for 30 s and the last 500 events;
  `session.resume { afterSeq }` replays them. Sticky routing on the ALB brings the
  resume to the task that holds the call; elsewhere it is `resume-unavailable`.
- **Alia ↔ Kaana:** `RealtimeSession.resume()` within Kaana's window; if that fails, or
  Kaana's task shuts down, a new session under the same call with fresh instructions
  from the stored messages (twice at most). The client shows `reconnecting`, never
  `listening`.
- A call ends on hang-up, the screen losing focus or changing conversation or account,
  `call-moved-elsewhere`, `max-duration` (with a warning a minute before),
  `idle-timeout`, `credits-exhausted`, a typed error, or `server-shutdown`. Each
  closes the Kaana session (which settles exactly once), stores what is left, settles
  the credits and ends the row.

### Typed failures

Every failure is `error { code, retryable, reference }` and then `session.closed` — the
realtime `failTurn`. Never a spoken "sorry", never text Alia did not hear. Kaana's
errors are recognized by their public `code` (`kaanaErrorOf`), so the real SDK's
classes and the fake's read the same:

| Error | `VoiceErrorCode` |
|---|---|
| unavailable, no model, Alia's credential refused | `realtime-unavailable` |
| rate, balance, spend, quota | `realtime-limited` |
| invalid or permission | `realtime-rejected` |
| provider failure, lost connection, contract violation | `realtime-failed` |
| Alia's own | `plan-required`, `credits-exhausted`, `not-authenticated`, `credential-not-supported`, `agent-unavailable`, `resume-unavailable`, `invalid-request` |
| the device (SDK) | `mic-denied`, `mic-unavailable`, `connection-lost`, `voice-unavailable` |

The app says each in its own language (`voice.errors.*`, `voice.ended.*`).

### Credits

A call is a paid-plan feature (`voice-mode`) and costs credits per minute at the
**real cost** of the model that serves it: the session's minutes, silence included,
at its catalogue `pricePerMinute`, converted with `creditsForCost`
(`lib/voice/credits.ts`). A block of five minutes is
held at open, the next one a minute before the held one runs out; a refused block
ends the call with `credits-exhausted` after the answer being spoken. At the end the
call is settled from the sessions' minutes. Silence costs too on a session-time
model; the idle timeout bounds it. Alia sets **no** concurrency or spend cap of its
own: those are the Alia app's policy in Oxy Console. No `voice-minutes` allowance
returns (ADR 0013, ADR 0005).

### The client

`useVoiceRoom` (`@alia.onl/sdk/voice`) runs the socket (`src/lib/voice-call.ts`) over
an audio-engine seam (`src/lib/voice-audio-engine*.ts`):

- **Web:** `getUserMedia` with echo cancellation, noise suppression and gain control;
  an `AudioWorklet` that downsamples to 24 kHz PCM16 and a second that plays a
  jitter-buffered queue, in one `AudioContext`. Firefox now has calls.
- **iOS / Android:** `react-native-audio-api` (0.13.6), capture and playback in one
  engine; iOS session `playAndRecord` in `voiceChat` mode. **It needs a new native
  build** (config plugin in `app.json`), and Android's echo cancellation is not
  engaged by this version (no `voiceCommunication` input preset) — a release gate
  (below).

States are honest: `connecting` → `listening` **only** after `session.ready`, the
engine's first captured buffer **and** `input.ready`; `user-speaking`, `thinking`,
`using-tool`, `speaking` (when the first frame actually plays), `reconnecting`,
`ended { reason }`, `error { code }`. Levels come from the real buffers; no state is
inferred from a timer. Mute stops sending audio.

The call is part of the SDK's conversation screen (`AliaChatContent`, so the sheet,
`AliaChatScreen` and the app alike): the button, the bar, the notices (failure, moved to
another device, time limit) and the transcript. `VoiceSession` says what happened through
`labels` and `onNotice`; `useVoiceLauncher` owns the gate (`canStartVoice` /
`onVoiceBlocked`), the end of a call that stops being the screen's (`owner`, `isFocused`)
and `onCallEnded`. The app only answers them (`features/chat/runtime/use-app-voice.ts`:
its API, the voice and `speechLocale()`, plan and credits, what to refresh on
`messages.saved` and at the end) and supplies the catalogue
(`features/voice/ui/voice-labels-provider.tsx`).

## Dictation

`POST /v1/audio/transcriptions` (`routes/v1/audio.ts`, `lib/voice/transcribe.ts`):
multipart `file`, `language`, `durationMs`. Batch, not a streaming session. The model
is computed — `audio_transcriptions`, the clip's media type, the language, the cheapest
per audio millisecond — and tried at most three times, only on a model refusal.

- **Free on every plan**, the free one included: no plan feature, no credits (its cost
  is Alia's internal cost centre, ADR 0005). A person's session only; an `oxy_sk_` is
  refused (`CREDENTIAL_NOT_SUPPORTED`). Bounded by the 5-minute clip, Kaana's 20 MiB
  and the `/v1` rate limit.
- Typed answers: `TRANSCRIPTION_UNAVAILABLE` 503, `TRANSCRIPTION_LIMITED` 429,
  `TRANSCRIPTION_REJECTED` 422, `TRANSCRIPTION_FAILED` 502, `CLIP_TOO_LONG` 413,
  `INVALID_REQUEST` 400. Never partial or invented text.
- The clip lives in memory for the one request; nothing is stored.

`useDictation`: web `MediaRecorder` (`audio/webm;codecs=opus`, or `audio/mp4` on
Safari) with a real level meter; native the `expo-audio` recorder (m4a → `audio/mp4`).
States `idle` → `requesting-permission` → `recording` (only once the recorder started)
→ `transcribing` → `idle`, or `error { code }`. The remaining time shows in the last
30 s and the recording stops at 5 minutes. A failed transcription keeps the clip for
one retry. Dictation and a call never record together: the call bar replaces the
composer.

## Read aloud

Unchanged by ADR 0017: `POST /v1/audio/speech` in the product voice, `male` or
`female` (no upstream voice name is ever sent or shown), through
`lib/synthesize-speech.ts`. A call no longer uses it: the realtime model speaks.

### When speech fails

The route answers a typed code with a provider-neutral, fixed message:

| Route answer (`error.code`) | Status |
|---|---|
| `SPEECH_UNAVAILABLE` — no inference client, no speech model, no route, storage not set up, Oxy refusing Alia's authority | 503 |
| `SPEECH_LIMIT_REACHED` — rate limit, quota, spending limit, balance (`Retry-After` when Oxy gave one) | 429 |
| `SPEECH_REJECTED` — the model refused the voice, the speed or the text | 422 |
| `SPEECH_PROVIDER_FAILED` — upstream error, timeout (504), transport, not MP3 | 502 / 504 |
| `SPEECH_GENERATION_FAILED` — storing or attaching the clip failed | 502 |

The route's message is provider-neutral and fixed per code; Oxy's `requestId`
travels with it. On the device, `requestSpeechClip` throws a `SpeechClipError`
that keeps the HTTP `status`, the typed `code` (`null` for a network failure or
a code the SDK does not know), `retryable` and `requestId`.

**Server side**, `lib/synthesize-speech.ts` is the only caller of the inference
client for speech and the only reader of its error type; the route and the show
pipeline see a `SpeechSynthesisError`. It tries the speech models in the
catalogue's order ([Model abstraction](./model-abstraction.mdx)) and moves to
the next — at most three, within one 60-second budget — only when the model
itself refused (`invalid_request`, `unsupported_modality`, `model_not_found`,
`no_route_available`, `commercial_permission_denied`); every other refusal,
authentication and credit above all, fails at once. Each failed request is one
structured `speech` log record — `code`, `reason`, `status`, Oxy's
`upstreamCode` / `upstreamStatus` / `requestId` / `param`, the models tried,
the product voice and the input's length — and never the text, the user or the
conversation. Each fallback is a `warn` record of the same kind.

### A clip is made once

Speech is paid per character, so `POST /v1/audio/speech` never synthesizes the
same thing twice for the same person (`lib/speech-clips.ts`). A reply read aloud
again — here or after a reload — is answered from storage, without calling Oxy.

**The key.** `speech_clips.cache_key` is a SHA-256 of
`[key version, oxy user id, speech model, voice, speed, "mp3", exact text]`.
The person is in it, so a clip is never shared between people: how fast an
answer comes must not tell one person what another had read aloud. The text is
taken exactly (no trimming or case folding) and is not stored. The speed is
rounded to two decimals, and `1` counts as no speed at all — that normalized
value is also what synthesis is sent, so the key describes the request made.

**The model.** A clip is keyed by the model that made it. Before synthesizing,
the request is looked up under every model `synthesizeSpeech` would try, in its
order (from the cached catalogue, no inference call), and the best-ranked stored
clip answers. A fallback therefore pays once: if the first model always refuses
this voice or speed, the second model's clip answers every later request. A
model that has left the candidates is never served; a new first model is used
for text that has no clip yet.

**A saved message.** `conversationId` + `messageId` must name the person's own
message (404 before anything is made otherwise). The clip is then filed under
that conversation — the first conversation that asks claims a clip that has
none, and it is never moved. `messages.audio_url`, which held one clip per
message whatever its voice or speed, is gone (`0093_drop_message_audio_url`,
post phase); the client always asks the route, and a stored clip is an instant
answer. `requestId` is in the answer only when that request made the clip.

**Two identical requests at once** are joined inside one API task: one
synthesis, and it is cancelled only when every request waiting for it has gone.
Across ECS tasks there is no lock: two tasks can each pay once for the same clip
in the same moment; the index keeps the first object and the other task deletes
its own. A clip whose synthesis has finished is stored even if the person has
left, so the next request is a hit.

**Where clips go.**

- Deleting a conversation (`DELETE /conversations/:id`) or clearing it
  (`DELETE /conversations/:id/messages`) deletes its clips first — rows and
  objects in one transaction, so if storage refuses the request fails with the
  thread intact and can be repeated.
- A clip unused for 30 days (`SPEECH_CLIP_RETENTION_DAYS`; every hit restarts
  the clock) is deleted by an hourly sweep on the leader task. This is what
  collects the sentences the retired on-device call loop had read aloud, which no
  saved message asks for, and the clips `messages.audio_url` held, which `0093`
  hands to the sweep already expired.
- Alia has no account-erasure path today. When it has one, a person's clips are
  their `speech_clips` rows and the objects under `<env>/tts/<oxy user id>/`;
  the sweep bounds them meanwhile.

The `speech_clips` row is the truth about its object: only `lib/speech-clips.ts`
deletes `tts/` objects. The media bucket has no lifecycle rule, and none may be
added on `tts/` — it would leave rows answering with links to nothing.

**Observability.** Every served clip is one `speech` `info` record, `Speech
clip served`, with `cache: "hit" | "miss"` (`miss` is a paid synthesis),
`inflight` (answered by another request's synthesis still running), the model,
the product voice and the input's length — never the text, the user or the
conversation. Each sweep logs `Speech clip sweep complete` with the clips and
objects removed, the empty runs included.

## Privacy

**Audio now reaches Alia, Kaana and the serving provider** — for a call, the
microphone stream; for dictation, the recorded clip. Alia logs no audio and no
transcript content (codes, sizes, durations and model ids only). The browser's and
the operating system's recognizers are no longer used: Chrome no longer sends a
dictation to Google's recognizer.

## What is left

Outside Alia, before calls and dictation can be switched on in production
(ADR 0017 §6):

- **Kaana phase 1:** enable and meter `inputAudioTranscription` inside realtime
  sessions (today refused) and publish the catalogue flag that says a realtime model
  does it (Alia reads `capabilities.realtime.inputAudioTranscription`; rename here if
  Kaana chooses another name); publish `audio` (voices with `gender`, languages) for
  realtime models; `capabilities.realtime` from Kaana's inventory; measure an upload's
  duration before the grant.
- **Oxy phase 2:** grant terms for `alia-kaana` `realtime_session` and
  `audio_transcriptions`; session concurrency and spend as Console policy; the
  transcription hold from the measured duration; service tokens with `aud: kaana.ai`.
- **Kaana phase 3 / oxy-infra:** `/v1/realtime` and `/v1/audio/transcriptions`
  public and `@kaana.ai/sdk` 1.0.0 published; ALB cookie stickiness and a
  deregistration delay of at least 31 min on Alia's target group; WebSocket idle
  timeouts that cover a 30-minute call.
- **Alia phase 4:** the switch in `lib/kaana/transport.ts` is done (usage units now come
  from `@kaana.ai/contracts`); left are the release gates: Chrome echo cancellation with Web
  Audio playback (fallback: an `RTCPeerConnection` loopback), Android echo
  cancellation with `react-native-audio-api` (fallback: a small Expo module of Alia's
  own over `AudioRecord(VOICE_COMMUNICATION)`), iOS on a Mac, dictation latency end to
  end — recorded in [Native validation](./native-validation.mdx#9-voice-through-kaana-to-validate).
