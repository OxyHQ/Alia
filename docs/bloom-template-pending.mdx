# Bloom AI Chat template: what is still to come back

In September 2026 the app adopted Bloom 4.5's AI Chat template
(`templates/ai-chat/AiChatTemplate.tsx` in Bloom) **as it is**: the shell, the
sidebar, the chat container, the composer and the turns are the template's
components with the template's props, and nothing Alia drew itself sits between
them. The only surface of Alia's own that stayed is the signed-out welcome
(`welcome-intro.tsx` over `ambient-field.tsx`).

Everything below was removed from the UI to get there. The data behind each item
(stores, hooks, API) is untouched; each comes back **through a Bloom slot**, never
as a component of Alia's placed around the template.

## Sidebar

Restored through the slots below (`src/shell/sidebar.tsx`,
`src/shell/sidebar-menus.tsx`, placement rules in `sidebarSections` of
`src/shell/sidebar-history.ts`):

| Restored | Through |
| --- | --- |
| Per-chat menu: rename, pin, favorite, move to project, move to folder, delete | `SidebarTreeItem.actions` |
| Project menu: edit, delete; folder menu: rename, delete; "New project" / "New folder" | `SidebarTreeFolder.actions`, `SidebarTree.actions` |
| Pinned, Favorites, projects and folders as their own groups | `tree.folders` |
| Agents section (one row per agent, opening its `/@handle` thread) | a `tree` folder |
| History grouped Today / Yesterday / Previous 7 days / Earlier | `tree.folders` |
| Loading skeleton, "Loading conversations…" | `content` |
| Streaming spinner on the chat being answered | `SidebarTreeItem.actions` |
| Unread notifications badge | `SidebarNavItem.badge` |
| Invite a friend, app download (web), privacy, terms | `secondaryItems` |
| Conversation search (it pages in older history while a query is typed) | the Sidebar's own quick search, controlled |

A chat is filed in one place at most (its project, else its folder, else
History); Pinned and Favorites are shortcuts that take it out of History but
not out of its project or folder.

Still to come back:

| Removed | Comes back through |
| --- | --- |
| Keyboard shortcuts row (the dialog is still ⌘/ and in the command palette) | `secondaryItems`, once Bloom has a keyboard glyph |
| Favourite a folder (sorted first) | `SidebarTreeFolder.actions` |

Kept, invisible: cursor pagination (`onScroll`) and prefetch on hover (`onPrefetch`).

## Chat container

| Removed | Comes back through |
| --- | --- |
| Header menu: ghost mode, clear, search the thread, export Markdown | `AiChatContainer.actions`: **back** as `ChatHeaderActions` (Bloom `DropdownMenu`) with search, export, delete and **Clear conversation** — confirmed with Bloom's `confirm`, cleared on the server first (`clearConversation`, #553). Ghost mode is still missing |
| Share | `AiChatContainer.onShare` |
| Credit warning and usage-limit banners | **back** as Bloom `toast`s (`src/features/chat/runtime/use-credit-warnings.ts`): under 50 credits once per account and session, and the server's spending warning (`alia_usage.credit_warning`, which the stream had stopped reading) once per turn that carries it. Both read the person's own balance and spend, never an error (#608 §8). Not restored: the banner's "switch to a cheaper routing profile" suggestion, and the "limit reached" banner (`UsageLimitDialog` answers the failure) |
| "Editing message" banner | the composer's `placeholder` + `toast` |
| Scroll-to-bottom button | `AiChatThread`'s own follow (no Bloom control yet) |
| Local models invite | **back** as a Bloom `toast` with the two answers (`src/features/chat/runtime/use-local-models-invite.ts`): signed in, large screen, once, only while the chat — not "Meet Alia" — is on screen, and withdrawn if the welcome returns. The artwork did not come back: a toast has no image slot |
| Agent terminal | **back** in the shell's `panel`: the code panel's second (`browser`) tab, opened from the chat menu's "Agent terminal" in an agent's thread or a chat whose turn started an agent run, and from the panel's terminal glyph. Kept to the route it was opened on; xterm still loads only when shown |

## Composer

| Removed | Comes back through |
| --- | --- |
| Suggestion autocomplete | no Bloom slot yet |
| Voice mode button in the send slot | `ComposerPill.emptyAction` |
| Dictation bar (cancel / stop / send while recording) | the pill's own mic (`listening`); today it records and transcribes into the draft |
| Drop-a-file overlay | no Bloom slot yet (paste still works) |

The composer is Bloom's `ComposerPanel` rather than the template's pill: its
model picker (the catalogue's real models by publisher and this device's, each a
rail group), the effort chip where the chosen model lists levels, the mode
selector (Chat, Agent — the panel's permission pill; deep research is a tool in
the add menu), the attachment tiles with
real read progress, and the chat's project as the status tab. A file that could
not be read is a toast; the tiles have no error state.

## Thread

| Removed | Comes back through |
| --- | --- |
| Read aloud, generate audio, regenerate | **back** as the feedback row's `actions` (Bloom 4.20): read aloud is a toggle — pressed while it plays, a second press stops it — disabled during a call or a dictation, and a call or a dictation that starts stops it (`src/features/chat/ui/turn-actions.tsx`); a failure is a toast. Regenerate is on Alia's last reply only, once it has finished and no turn is in flight, and replays its question with the connector and skills it was sent with (the composer's, for a question sent before a reload). Copy confirms only what the clipboard did: a refusal is an error toast and no "Copied!". **Generate audio stays out:** `POST /v1/audio/generate` answers 503 `KAANA_CAPABILITY_UNAVAILABLE` on every request |
| Copy / edit under the user's turn | **back** as `AiChatUserMessage.actions`. Edit puts the question's words and its connector and skills into this chat's draft (`composer-draft-store.ts`, `editing`), with "Edit your message" as the placeholder and an "Editing message · Cancel" strip where the status tab sits; Cancel gives back what the composer held, and the send replaces the question and everything after it (`src/features/chat/runtime/use-turn-edit.ts`). Not on a question from an earlier conversation of a thread, nor during a call |
| Long-press menu on native | **back**: Bloom's `ContextMenu` around each turn, with the same actions (likes included on a reply). Web keeps the rows; a right-click there stays the browser's |
| Weather, market, FairCoin and scheduled-task cards | blocks inside `AiChatAssistantMessage` |
| Sources under a reply and the reference list | `AiChatLinkChip`s (inline citations are already chips) |
| Research progress card | `AgentProgress` |
| "Reasoning" trigger into the thought panel | **back**: a finished turn's "Worked for …" line, or a "Reasoning" line on a turn that reasoned without tools, opens the thought panel on that turn in the conversation it belongs to (`src/features/chat/runtime/use-open-thought.ts`) |
| Day separators and "new stretch" seams | back as rows: `ChatDateHeader placement="inline"` and a labelled `Divider` |
| "Hi {name}, what's on your mind?" | no Bloom slot yet — the template has no empty state |
| Rich blocks (`[BANNER]`, `[TIMELINE]`, `[COMPARISON]`…) | they render as text today |

Still Alia's, pending a Bloom equivalent: `FailedTurnCard` (retry),
`NewConversationOffer`, `PlanPreviewCard` (approve / reject a plan),
`AgentTaskCard` / `AgentResultCard`, and the thread skeleton.

## Also different from the template on purpose

- **Colour preset:** Alia keeps `purple`; Storybook shows the template in `oxy`.
- **Logo:** Alia passes `logo` (mark + "Alia") as well as `account`; Bloom puts the
  account switcher on its own row under it.
- **Signed out:** the account is "Guest" and the plan card "Free Plan"; both sign in.
- **Breadcrumb and status tab:** the chat's folder as the sidebar files it, its
  project or "Recent". Moving a chat to another project comes back through the
  tree's item `actions`.
- **Effort:** the model menu shows the effort slider only for a mode that can send
  a level (`packages/api/src/lib/reasoning-effort.ts`: a level is offered only
  where it can be sent). "Auto" offers none, so its menu has no slider.
- **Right panel:** the code panel is the canvas (the files Alia wrote in this
  chat), the gallery shows Library images and the images generated in the chat.
  Thought, credits and agent open in the same slot and hand it back when closed;
  the agent terminal is the code panel's second tab.
